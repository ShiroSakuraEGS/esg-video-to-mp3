- 狀態：已批准建置（創辦人 t9u + widget 回答）

## 1. 背景與問題

創辦人需要一個可放在 GitHub Pages 的靜態工具，把使用者**自己擁有的**本機影片或音訊轉成 MP3。轉換必須完全在瀏覽器內完成，檔案不可上傳。已明確決定：**不做** YouTube／小紅書或其他平台的網址下載或抓取（法律風險）。

## 2. 產品目標

- 主要目標：使用者可在無後端、無 COOP/COEP 的 GitHub Pages 環境，將本機常見影音檔轉成可下載的 MP3（可選位元率與裁切），並理解隱私與著作權界線。
- 非目標：網址下載、影音平台擷取、雲端轉檔、帳號系統、批次伺服器處理、將他人受保護內容做未授權轉換的協助。

## 3. 目標使用者

| 使用者 | 情境 | 痛點 | 期望 |
|---|---|---|---|
| 創辦人／學員／一般使用者 | 把自己拍的或已授權的影片抽出音訊 | 線上轉檔要上傳檔案 | 本機完成、介面清楚 |
| 行動裝置使用者 | 在手機選擇相簿中的影片 | 小螢幕難操作、記憶體有限 | 可點選、錯誤訊息清楚 |

## 5. 成功標準 / 驗收摘要

- [x] 本機靜態伺服器**未**設定 COOP/COEP 時，可將測試用 mp4／webm／mov 轉成有效 MP3（以實際測試為準，見 06_TEST_REPORT）
- [ ] 多檔佇列、裁切、位元率（見測試報告）
- [ ] 介面有隱私／著作權聲明，且沒有網址輸入或平台下載功能
- [ ] 文件、NOTICE、Pages 工作流程齊備；未推送、未發信

## 6. 限制與假設

- 技術限制：GitHub Pages 為靜態網站，不能設 COOP/COEP，也不宜提交單一超過 100 MB 的 git 物件。
- 預算：無付費 API。使用已內嵌的開源函式庫（注意 GPL／LGPL）。
- 時程：本次直接建置並本機測試。
- 假設：使用者使用較新的 Chrome／Edge／Safari；單一檔案建議小於 80 MB。

## 7. 可行性與風險

| 風險 | 可能性 | 影響 | 對策 |
|---|---|---|---|
| 多執行緒 ffmpeg 在 Pages 無法執行 | 高 | 轉換失敗 | 只用單執行緒核心 |
| 瀏覽器解碼不了 mkv／部分 mov | 中 | 部分檔失敗 | ffmpeg.wasm 後備 |
| 大檔記憶體不足 | 中 | 分頁崩潰 | 大小上限與清楚錯誤 |
| 授權散布義務（GPL core） | 確定存在 | 合規 | NOTICE 與授權建議稿誠實標明 |
| 被誤用為盜版下載器 | 中 | 法律風險 | 不做網址功能；頁面聲明只轉自己有權的內容 |
